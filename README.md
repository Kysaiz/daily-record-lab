# daily-record-lab

用于观察GMS公开排行榜数据的小规模实验，仅手动启动。

## 测试范围

使用一个标准Ubuntu runner、一个HTTPS连接，整体速率为每秒0.4次请求。读取Bishop职业榜在两种服务器类型合并范围内的前100个非重叠页面，随后复查首尾两个页面。最多发送102次GET请求。

该测试只覆盖一个小分片，不代表整个Bishop职业或全部LV275+角色已采集完成。

## 停止条件

出现HTTP拒绝、网络错误、空页或不足10条的页面、职业不符、角色重复、totalCount变化或首尾校验变化时，立即结束。不重试，不变换身份，不自动安排后续运行。

## 如何运行

打开仓库的Actions，选择Single-runner integrity observation，点击Run workflow。直接运行probe_job_pages.py但不加--execute时，只打印测试计划，不发送请求。

## 如何验收

下载single-runner-observation结果包，检查report.json：

- status为complete_sample。
- 成功扫描100页，取得1000个不同的角色。
- duplicate_rows为0，首尾校验一致。

任务显示绿色只表示本次执行完成，不能证明全量采集可靠或长期不会限流。

## 数据与限制

结果包保留3天，包含官方公开角色记录、图片URL和逐请求时间及状态，不下载图片文件。日志中的socket本地地址可能是云环境内网地址，不是测得的公网出口IP。

无需提供账号密码、Nexon凭据或NAS数据库。本实验不能单独确定官方限流规则，也不证明每日全量方案已经成立。

## Hero 职业 LV275+ 完整范围观察

Actions 中新增 Single-class LV275 observation，仅手动启动。北京时间2026年10月12日11:45本机15次请求确认，Hero 在两种服务器合并范围内有6680个LV275+角色、668页。云端会重新定位边界，再从列表位置1、11、21依次读取到等级边界，保持每秒0.4次请求、单连接、单runner。

此作业最多扫描750页，总请求上限790次，程序运行上限40分钟，作业上限45分钟。出现拒绝、网络错误、重复角色、等级顺序异常、totalCount或边界变化即停止，不重试、不自动续跑。NAS设置不会改变，也不会自动安排跨日测试。

结果包 hero-lv275-observation 保留3天，保存逐次响应、请求日志、boundary.json 和 report.json。验收需要 status 为 complete_class_observation、成功页数等于预期页数、rows 和 unique_characters 均等于 last_qualifying_position、duplicate_rows 为0，前中后三个页面和边界两次复查全部一致。

这是顺序采集，官方接口没有提供快照标识。有限页面复查不能排除所有未观察到的变化；单次完整范围通过也不证明连续每日全量稳定。第一轮完成后再决定跨日复测。

## 低速完整范围观察

10月12日0.4次/秒这一轮在第123次请求遇到429，保存108页、1080个角色，未完成完整范围。发送间隔均不小于2.5秒，因此没有证据将此次拒绝归因于发送挤压。

新增 Single-class slow observation，仍仅手动启动。一次使用同一runner、单连接，以0.1次/秒采集同一Hero LV275+范围，扫描上限750页、全阶段最多790次官方请求、程序150分钟、作业160分钟。按照当前668页估计需要约1小时55分钟；所有停止与完整性条件保持一致，首次拒绝立即结束，不自动重试或接续其他环境。

结果包 hero-slow-observation 保留3天。开始和结束各向ipify发出一次IPv4出口诊断请求，保存环境与公网IPv4；诊断失败只记为未知，不伪造地址。该地址由外部服务观测，不是Nexon直接确认的出口，也不能证明与之前runner使用同一出口。不会输出凭据或完整环境变量。

## 参考公开项目的异步职业采集验证

参考 ebenitez1/maplestory-level-stats 的职业矩阵、aiohttp连接池、每批5个异步请求和批间0.5秒暂停结构，加入准确列表位置、去重、真实LV275边界和完整范围复查。初始矩阵仅Hero；一个仓库可调度多个runner，后续扩大矩阵需先检查当前结果。

选择 Corrected class batch observation 手动运行。全阶段最多790次请求、750扫描页、程序15分钟、作业20分钟。page_index以1、11、21递增，空页/短页、网络、HTTP拒绝、职业或等级顺序异常、重复、totalCount或锚点变化均判为不完整，退出码2。失败取消本批未结束任务，没有下一批或重试；已在途请求可能已发出或完成，不宣称拒绝后零在途请求。

使用固定aiohttp3.14.3并关闭其持久GET内部重试，不冒用原作者User-Agent。原项目声称约800次按IP限制尚未在本项目确认，不能写作已知事实。相比原项目还显式使用reboot_index=0和LV275范围，属于修正后的结构验证而非逐字复现原版。

每个runner独立保存开始/结束IPv4、职业、运行编号、系统及客户端版本。结果包按矩阵编号命名class-batch-0等，保留3天，含逐次响应、按发起顺序的requests.jsonl、完成顺序日志和report.json；configured_rps为空表示批次并发，不代表限速0.4。成功仍需唯一目标数量=真实边界、全部扫描页、最终锚点一致；不得把绿色运行或重复累加数当全量。

## 47职业矩阵与429冷却验证

新增 Original class matrix with bounded cooldown。原仓库47个职业各一个作业，同时最多8个标准runner；仅手动运行，没有日程。范围为两种服务器合并的LV275+，职业清单沿用原仓库，不能直接视作已覆盖全部GMS职业。各职业失败不取消其他职业，也不启动替代runner接续失败职业。

每批最多5个请求，批间暂停0.5秒，列表位置按1、11、21递增。429后在同一runner统一暂停，最多4次尝试同一页；默认等待30、60、90秒，若Retry-After更长则遵守（超过600秒直接结束本次观察）。不保留原版最后一次失败后无意义的120秒等待。403、网络或一致性错误停止该职业。每职业最多12个429响应、40次额外尝试、3000扫描页和25分钟，作业上限30分钟；任何上限耗尽都判为不完整。

保存每个runner开始/结束IPv4、全部原始响应、尝试时间、冷却起止和角色记录。结果包matrix-class-序号与matrix-summary保留1天。汇总明确缺失/不完整职业、跨职业重复和总耗时；原始证据还需离线复核。失败、意外空页或职业名称不匹配不会计作完整的零人口。
